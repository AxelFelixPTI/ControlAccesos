# Equivalencias PostgreSQL → SAP HANA

Versión V1.1 · 2026-10-11 · se amplía con cada procedimiento nuevo.

El piloto se escribe en PostgreSQL usando **solo lo que tiene equivalente directo en HANA**. Esta tabla es la guía para escribir y, antes del despliegue, para traducir. Regla de oro: **los nombres de schemas, tablas, columnas, procedimientos y parámetros son idénticos en los dos motores**; solo cambia la sintaxis.

## 1. Tipos de dato

| PostgreSQL (piloto) | SAP HANA (destino) | Nota |
| --- | --- | --- |
| `VARCHAR(n)` | `NVARCHAR(n)` | En PostgreSQL todo texto ya es Unicode. Tope en HANA: 5000. |
| `TEXT` | `NCLOB` | Solo con comentario de sustento; **prohibido en catálogos**. |
| `CHAR(1)` con `'Y'`/`'N'` | `CHAR(1)` con `'Y'`/`'N'` | Igual. Nunca `BOOLEAN`. |
| `BIGINT` | `BIGINT` | Igual. Nunca `INT` en tablas. |
| `DECIMAL(18,4)` | `DECIMAL(18,4)` | Igual. |
| `TIMESTAMP` | `TIMESTAMP` | Igual. Hora de Lima la fija el servidor de aplicación (RN-18). |
| `BIGINT GENERATED BY DEFAULT AS IDENTITY` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | **Misma sintaxis.** |
| `INT` en parámetros (`HV_Codigo_Resp`) | `INT` | Igual; `INT` sí se permite en parámetros. |

## 2. DDL

| PostgreSQL | SAP HANA | Nota |
| --- | --- | --- |
| `CREATE SCHEMA IF NOT EXISTS "X";` | `CREATE SCHEMA "X";` | HANA no admite `IF NOT EXISTS`: ejecutar una vez. |
| `SET search_path TO "X";` | `SET SCHEMA "X";` | Debe ser una sentencia, no un comentario. |
| `CREATE TABLE "T" (...)` | `CREATE COLUMN TABLE "T" (...)` | Siempre `COLUMN` en HANA. |
| `CONSTRAINT "PK_T" PRIMARY KEY (...)` | Igual | |
| `CONSTRAINT "UQ_T_Col" UNIQUE (...)` | Igual | |
| `CONSTRAINT "CK_T_X" CHECK (...)` | Igual | |
| `CONSTRAINT "FK_T_R" FOREIGN KEY ... REFERENCES ...` | Igual | Solo dentro del mismo schema (decisión D-06). |
| `CREATE INDEX "IX_T_X" ON "T" (...)` | Igual | |
| `COMMENT ON TABLE "T" IS '...'` | `COMMENT ON TABLE "T" IS '...'` | Igual. |
| Índice parcial (`... WHERE`) | No existe | **No usar.** |

## 3. Procedimientos

| Concepto | PostgreSQL | SAP HANA |
| --- | --- | --- |
| SP de **lectura** (`LISTAR`, `DETALLE`, `DROPDOWN`) | `CREATE OR REPLACE FUNCTION "ERP_..."(...) RETURNS TABLE (...) LANGUAGE plpgsql` + `RETURN QUERY SELECT ...` | `CREATE OR REPLACE PROCEDURE ERP_...(...) LANGUAGE SQLSCRIPT AS BEGIN SELECT ...; END;` |
| Cómo se llama una lectura | `SELECT * FROM "ERP_..."(...)` | `CALL ERP_...(...)` |
| SP de **escritura** (`CREAR`, `ACTUALIZAR`, `ELIMINAR`) | `CREATE OR REPLACE PROCEDURE "ERP_..."(...) LANGUAGE plpgsql` | `CREATE OR REPLACE PROCEDURE ERP_...(...) LANGUAGE SQLSCRIPT AS` |
| Parámetro de salida | `INOUT "HV_X" tipo DEFAULT NULL` (al final) | `OUT HV_X tipo` |
| Nombre del SP | Entre comillas y en mayúsculas: `"ERP_..."` | Sin comillas: `ERP_...` (HANA lo pasa a mayúsculas) |
| Leer un parámetro | `"HV_Codigo"` | `:HV_Codigo` |
| Asignar | `"HV_Codigo_Resp" := 100;` | `HV_Codigo_Resp := 100;` |
| Variable local | `DECLARE lv_x INT := 0;` antes de `BEGIN` | `DECLARE lv_x INT := 0;` dentro, al inicio |
| Manejo de error | Bloque interno `BEGIN ... EXCEPTION WHEN OTHERS THEN ... END;` **al final** | `DECLARE EXIT HANDLER FOR SQLEXCEPTION BEGIN ... END;` **al inicio** |
| ID recién insertado | `INSERT ... RETURNING "ID_X" INTO "HV_ID_X_Result";` | `SELECT CURRENT_IDENTITY_VALUE() INTO HV_ID_X_Result FROM DUMMY;` |
| `SELECT` sin tabla | `SELECT 1;` | `SELECT 1 FROM DUMMY;` |
| ¿Existe un registro? | `SELECT COUNT(*) INTO lv_n ...` y `IF lv_n > 0` | Igual. **No usar `IF EXISTS (SELECT ...)`** (HANA lo rechaza). |
| Condicional | `IF ... THEN ... ELSIF ... END IF;` | `IF ... THEN ... ELSEIF ... END IF;` |
| Salir del SP | `RETURN;` | `RETURN;` (nunca dentro del EXIT HANDLER) |
| Paginación | `LIMIT n OFFSET m` | Igual, pero solo con literal o variable, nunca una expresión. |
| Fecha y hora actual | `CURRENT_TIMESTAMP` | `CURRENT_TIMESTAMP` |
| Texto | `UPPER`, `TRIM`, `LENGTH`, `\|\|`, `COALESCE` | Igual |

**Contrato de salida (igual en los dos motores):** `HV_Codigo_Resp` y `HV_Mensaje` al final de los parámetros. 100 éxito · 101 regla de negocio · 400 validación · 404 no encontrado · 409 estado inválido · 500 error técnico. Los SP de lectura **no** llevan contrato ni manejo de error.

## 3-bis. Equivalencias encontradas al escribir la Fase 1 del Hito 0

| Concepto | PostgreSQL | SAP HANA |
| --- | --- | --- |
| Schema por defecto de una rutina | `SET search_path TO "X"` en la definición (D-28) | Automático: el schema donde se creó |
| Conflicto columna/variable en funciones `RETURNS TABLE` | `#variable_conflict use_column` al inicio del cuerpo, y columnas siempre con alias (`T0."Codigo"`) | No aplica: borrar la directiva |
| Sumar minutos a una fecha | `CURRENT_TIMESTAMP + (n * INTERVAL '1 minute')` | `ADD_SECONDS(CURRENT_TIMESTAMP, :n * 60)` |
| Posición de un texto | `POSITION('@' IN x)` | `LOCATE(x, '@')` |
| Resto de un texto desde una posición | `SUBSTRING(x FROM n)` | `SUBSTRING(x, n)` |
| Solo dígitos | `LTRIM(x, '0123456789') = ''` | Igual (`LTRIM` con conjunto de caracteres) |
| Concatenar un número | `'texto ' \|\| lv_n` (convierte solo) | `'texto ' \|\| TO_VARCHAR(:lv_n)` |
| Lista en un solo texto | `STRING_AGG(x, ', ' ORDER BY y)` | `STRING_AGG(x, ', ' ORDER BY y)` (verificar en la primera prueba) |
| `CASE WHEN EXISTS (SELECT ...)` en un SELECT | Admitido | Verificar; alternativa: `(SELECT COUNT(*) ...) > 0` |
| Primeras N filas | `LIMIT 6` | `LIMIT 6` (solo literal o variable) |
| Leer un parámetro `RETURNS TABLE` | `SELECT * FROM "ERP_X"(...)` | `CALL ERP_X(...)` |
| Zona horaria de `CURRENT_TIMESTAMP` | Hora de la sesión: configurar la base con `ALTER DATABASE ... SET timezone = 'America/Lima'` | Hora local del servidor HANA |
| Tabla de valores en línea | `(VALUES (...), (...)) AS v(col1, col2)` | **No existe.** Usar `SELECT ... FROM DUMMY UNION ALL SELECT ... FROM DUMMY` |

## 3-ter. Equivalencias encontradas al escribir la Fase 1 del Hito 1

| Concepto | PostgreSQL | SAP HANA |
| --- | --- | --- |
| Tabla del schema transversal dentro de una rutina del módulo | Calificada: `"CAF_GOVERNANCE"."Usuario"` (el `search_path` de la rutina es solo el del módulo, D-28) | Igual. Al integrar, reemplazar `"CAF_GOVERNANCE".` por `"TRIANONSATELITAL_GOVERNANCE".` (D-03). El schema del módulo nunca se escribe en el cuerpo |
| Filtro opcional por un valor cerrado en una lectura (`HV_Etapa`) | Variable con `'%'`, asignada antes del `SELECT`, y `T0."Etapa" LIKE lv_etapa` | Igual, con `:lv_etapa`. Evita los `OR` anidados que mezclan variable y columna, que HANA rechaza |
| Variables en una función de lectura | `DECLARE` entre `#variable_conflict use_column` y `BEGIN` | `DECLARE` al inicio del cuerpo del procedimiento |
| Rama alternativa | `ELSIF` | `ELSEIF` |
| Rutina que nombra una tabla o columna inexistente | **Se crea sin error**; falla recién al llamarla | **No se crea** el procedimiento |

La última fila decide cómo se verifica: en PostgreSQL contar las rutinas no prueba nada, por eso el script de pruebas **llama a cada una** (en el Hito 1, las 43). En HANA, el conteo en `SYS.PROCEDURES` sí es una prueba.

## 3-ter. Equivalencias del script 09 (permisos y pasos de aprobación)

| Concepto | PostgreSQL | SAP HANA |
| --- | --- | --- |
| Ampliar los valores de un `CHECK` | `ALTER TABLE ... DROP CONSTRAINT` + `ADD CONSTRAINT` | Igual: no existe "modificar"; se borra y se vuelve a crear |
| Quitar la obligatoriedad de una columna | `ALTER COLUMN "X" DROP NOT NULL` | `ALTER TABLE "T" ALTER ("X" <tipo> NULL)` (se repite el tipo) |
| Agregar una columna con valor por defecto | `ADD COLUMN "X" CHAR(1) DEFAULT 'N' NOT NULL` | `ALTER TABLE "T" ADD ("X" CHAR(1) DEFAULT 'N' NOT NULL)` (paréntesis) |
| Recibir una lista de códigos en un parámetro | Texto con comas, normalizado a `,COD1,COD2,` y comparado con `LIKE` | **Igual**: se eligió así a propósito, para no usar tablas temporales ni `UNNEST` |
| Validar que todos los códigos existan | `REGEXP_SPLIT_TO_TABLE` sobre el parámetro | `SERIES_GENERATE` + `SUBSTR_REGEXPR`, o un bucle `WHILE` sobre la lista |
| Tabla temporal dentro de un procedimiento | `CREATE TEMP TABLE ... ON COMMIT DROP` | **Evitar**: en HANA la tabla temporal es de sesión, no de transacción. Además falla al llamar dos veces el mismo procedimiento en una transacción (error medido el 2026-10-16) |
| Texto de la izquierda | `LEFT(x, n)` | `LEFT(x, n)` |
| Reemplazar caracteres | `REPLACE(x, a, b)`, `CHR(9)`, `CHR(10)` | `REPLACE(x, a, b)`, `CHAR(9)`, `CHAR(10)` |


## 4. Ejemplo probado: el mismo SP en los dos motores

> **Nota (2026-10-11).** Este ejemplo es anterior a D-24. El procedimiento real (`SP_CAF_CATALOGO_MOTIVO_VISITA_ALL.sql`, generado) guarda el código en MAYÚSCULAS y busca el duplicado también entre eliminados. Para HANA se traduce ese archivo, no este ejemplo.

Probado el 2026-10-09 en PostgreSQL 16.15: devuelve 100 al crear, 101 con código repetido y 400 con código vacío.

**PostgreSQL (piloto)**

```sql
SET search_path TO "TRIANONSATELITAL_CAF_PRODD";

CREATE OR REPLACE PROCEDURE "ERP_CATALOGO_MOTIVO_VISITA_CREAR"(
    IN    "HV_Codigo"           VARCHAR(50),
    IN    "HV_Descripcion"      VARCHAR(500),
    IN    "HV_Es_Otro"          CHAR(1),
    IN    "HV_Orden"            BIGINT,
    IN    "HV_Activo"           CHAR(1),
    IN    "HV_UsuarioID_Create" BIGINT,
    INOUT "HV_ID_Catalogo_Motivo_Visita_Result" BIGINT DEFAULT NULL,
    INOUT "HV_Codigo_Resp"      INT DEFAULT NULL,
    INOUT "HV_Mensaje"          VARCHAR(250) DEFAULT NULL
)
LANGUAGE plpgsql AS $$
DECLARE
    lv_duplicado INT := 0;
BEGIN
    -- V1.0 2026-10-09
    "HV_Codigo_Resp" := 500;
    "HV_Mensaje"     := 'Error interno en ERP_CATALOGO_MOTIVO_VISITA_CREAR';
    "HV_ID_Catalogo_Motivo_Visita_Result" := 0;
    BEGIN
        IF "HV_Codigo" IS NULL OR LENGTH(TRIM("HV_Codigo")) = 0 THEN
            "HV_Codigo_Resp" := 400; "HV_Mensaje" := 'El código es obligatorio.'; RETURN;
        END IF;
        IF "HV_UsuarioID_Create" IS NULL OR "HV_UsuarioID_Create" < 0 THEN
            "HV_Codigo_Resp" := 400; "HV_Mensaje" := 'Usuario no válido.'; RETURN;
        END IF;

        SELECT COUNT(*) INTO lv_duplicado FROM "Catalogo_Motivo_Visita"
         WHERE UPPER(TRIM("Codigo")) = UPPER(TRIM("HV_Codigo")) AND "Eliminado" = 'N';
        IF lv_duplicado > 0 THEN
            "HV_Codigo_Resp" := 101; "HV_Mensaje" := 'Ya existe un motivo con ese código.'; RETURN;
        END IF;

        INSERT INTO "Catalogo_Motivo_Visita" ("Codigo","Descripcion","Es_Otro","Orden","Activo","UsuarioID_Create")
        VALUES (TRIM("HV_Codigo"), TRIM("HV_Descripcion"), COALESCE("HV_Es_Otro",'N'),
                COALESCE("HV_Orden",0), COALESCE("HV_Activo",'Y'), "HV_UsuarioID_Create")
        RETURNING "ID_Catalogo_Motivo_Visita" INTO "HV_ID_Catalogo_Motivo_Visita_Result";

        "HV_Codigo_Resp" := 100;
        "HV_Mensaje"     := 'Motivo registrado correctamente.';
    EXCEPTION WHEN OTHERS THEN
        "HV_Codigo_Resp" := 500;
        "HV_Mensaje"     := 'Error interno en ERP_CATALOGO_MOTIVO_VISITA_CREAR';
        "HV_ID_Catalogo_Motivo_Visita_Result" := 0;
    END;
END;
$$;

CALL "ERP_CATALOGO_MOTIVO_VISITA_CREAR"('CAPACITACION','Capacitación','N',5,'Y',0);
```

**SAP HANA (destino, traducción a verificar en la oficina)**

```sql
SET SCHEMA "TRIANONSATELITAL_CAF_PRODD";

CREATE OR REPLACE PROCEDURE ERP_CATALOGO_MOTIVO_VISITA_CREAR
(
    IN  HV_Codigo                            NVARCHAR(50),
    IN  HV_Descripcion                       NVARCHAR(500),
    IN  HV_Es_Otro                           CHAR(1),
    IN  HV_Orden                             BIGINT,
    IN  HV_Activo                            CHAR(1),
    IN  HV_UsuarioID_Create                  BIGINT,
    OUT HV_ID_Catalogo_Motivo_Visita_Result  BIGINT,
    OUT HV_Codigo_Resp                       INT,
    OUT HV_Mensaje                           NVARCHAR(250)
)
LANGUAGE SQLSCRIPT AS
BEGIN
    -- V1.0 2026-10-09
    DECLARE lv_duplicado INT := 0;
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        HV_Codigo_Resp := 500;
        HV_Mensaje     := 'Error interno en ERP_CATALOGO_MOTIVO_VISITA_CREAR';
    END;

    HV_Codigo_Resp := 500;
    HV_Mensaje     := 'Error interno en ERP_CATALOGO_MOTIVO_VISITA_CREAR';
    HV_ID_Catalogo_Motivo_Visita_Result := 0;

    IF :HV_Codigo IS NULL OR LENGTH(TRIM(:HV_Codigo)) = 0 THEN
        HV_Codigo_Resp := 400; HV_Mensaje := 'El código es obligatorio.'; RETURN;
    END IF;
    IF :HV_UsuarioID_Create IS NULL OR :HV_UsuarioID_Create < 0 THEN
        HV_Codigo_Resp := 400; HV_Mensaje := 'Usuario no válido.'; RETURN;
    END IF;

    SELECT COUNT(*) INTO lv_duplicado FROM "Catalogo_Motivo_Visita"
     WHERE UPPER(TRIM("Codigo")) = UPPER(TRIM(:HV_Codigo)) AND "Eliminado" = 'N';
    IF :lv_duplicado > 0 THEN
        HV_Codigo_Resp := 101; HV_Mensaje := 'Ya existe un motivo con ese código.'; RETURN;
    END IF;

    INSERT INTO "Catalogo_Motivo_Visita" ("Codigo","Descripcion","Es_Otro","Orden","Activo","UsuarioID_Create")
    VALUES (TRIM(:HV_Codigo), TRIM(:HV_Descripcion), COALESCE(:HV_Es_Otro,'N'),
            COALESCE(:HV_Orden,0), COALESCE(:HV_Activo,'Y'), :HV_UsuarioID_Create);
    SELECT CURRENT_IDENTITY_VALUE() INTO HV_ID_Catalogo_Motivo_Visita_Result FROM DUMMY;

    HV_Codigo_Resp := 100;
    HV_Mensaje     := 'Motivo registrado correctamente.';
END;
```

## 5. Del lado de .NET

Solo el **ejecutor de procedimientos** (`Infrastructure.Persistence`) conoce el motor:

| | PostgreSQL (Npgsql) | SAP HANA (`Sap.Data.Hana`) |
| --- | --- | --- |
| Lectura | `SELECT * FROM "ERP_X"(@p1, @p2)` | `CALL ERP_X(?, ?)` con `CommandType.StoredProcedure` |
| Escritura | `CALL "ERP_X"(@p1, ..., NULL, NULL, NULL)` y se leen las columnas devueltas | `CALL ERP_X(...)` y se leen los parámetros `OUT` |

Repositorios, servicios y controladores llaman siempre `EjecutarLecturaAsync("ERP_X", parámetros)` o `EjecutarEscrituraAsync("ERP_X", parámetros)` y no saben qué motor hay detrás.

## 6. Registro de diferencias encontradas

| Fecha | SP o tabla | Diferencia | Cómo se resolvió |
| --- | --- | --- | --- |
| 2026-10-09 | Índices únicos | HANA no tiene índices parciales | `UQ_CAF_Persona_Externa_Documento` sin filtro; las personas no se eliminan |
| 2026-10-11 | `05_SEED_INICIAL.sql` (zonas de VES) y `MODELO_DATOS_ETAPA1_PRUEBA_RECORRIDO.sql` | Usan `(VALUES ...) AS v(...)`, que HANA no admite | Traducir a `SELECT ... FROM DUMMY UNION ALL ...` antes de ejecutar en HANA |
| 2026-10-11 | `_DETALLE` de Personal | Reutilizar `_LISTAR` no es portable | Se repite el `SELECT` (D-27) |
| 2026-10-16 | `ERP_LICENCIA_PERMISO_ASIGNAR` | La primera versión usaba `CREATE TEMP TABLE`, que falla al llamar el procedimiento dos veces en una misma transacción (lo detectaron las pruebas) | Reescrito con una lista `,COD1,COD2,` y `LIKE`: funciona igual en los dos motores |
| 2026-10-16 | Script 09 | Ampliar un `CHECK` y quitar un `NOT NULL` se escriben distinto en HANA | Anotado en la tabla 3-ter |
| 2026-10-11 | Rutinas del Hito 1 | PostgreSQL crea una función que nombra una tabla inexistente; HANA no | El script de pruebas llama a las 43 rutinas; en HANA se cuenta en `SYS.PROCEDURES` |
| 2026-10-11 | `_DROPDOWN` de tratamientos e ítems | Filtro opcional por etapa | Variables con `LIKE` en lugar de `OR` anidados (sección 3-ter) |
